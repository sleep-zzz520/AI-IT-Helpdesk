# 检索准确性与鲁棒性测评（2026-11-02）

在这套新的、有明确适用范围的合成运维测试集上，混合检索的 Recall@5 在 64/256/512 篇三档均高于同口径纯向量。512 篇、240 道冻结测试题、三组干扰抽样的平均结果为 **0.673 → 0.799，增加 12.57 个百分点**，MRR 为 **0.659 → 0.767**。这支持“引入词法路有助于抵抗同领域近邻干扰”的有限结论；旧 60 题的 0.917 不能直接外推到扩大后的新题。

收益有条件。64 篇时两方案 Recall@1 持平；512 篇口语子集的 BM25-only 比混合更好；双段题中混合找齐两段的比例只有 51.67%。本轮只测检索和排序，未测回答生成、工具执行或线上容量。

## 1. 数据、标注和冻结

来源是为虚构企业编写的中文内部运维手册，技术约定由模型撰写，不代表厂商规范或真实事故。没有把本地 CRUD-RAG 新闻来源池作为同领域质量证据：固定种子抽读的十篇均为新闻，抽样记录保留在 `scale-corpus-audit.json`。

输入池共 50 篇目标文档、600 篇干扰候选和 8 篇生命周期探针文档。主矩阵最多同时入库 **512 篇**，不是把整个候选池同时入库。每篇六个二级标题段，使用现有 `split_markdown`；单段约 100–225 字符，结构较统一。

- 50 个问题家族，每家族六个不同任务：术语归因、口语核查、条件恢复、验收、安全边界、恢复加升级交接。跨段题会复用恢复事实，并额外询问升级交接事实；不是六种同义改写，也不是 300 个独立事故。
- 共 300 题、350 条 Gold 段落标注。按整个家族分为开发集 10 家族/60 题、冻结测试集 40 家族/240 题。主结论只使用测试集；开发集另列在原始报告，本轮没有调参。
- 每题记录 query、conditions、Gold 文档/标题/段序号、逐字证据、参考答案和来源。测试集有 200 道单 Gold、40 道双 Gold；双 Gold 均在同一文档，未覆盖跨文档多跳。
- 三档共同包含全部 50 篇目标，其余为 14/206/462 篇干扰。种子 `20261102/20261103/20261104`，每种子内部 64 ⊂ 256 ⊂ 512，跨规模的题和 Gold 不变。索引包含开发和测试文档，问题家族不跨集合；检索不使用 split、Gold 或 scenario 过滤。
- 600 篇干扰的一半保留原技术事实、改变显式授权版本/环境，形成有意的近重复；另一半使用 50 组家族专属替代根因、核查、操作和验收，例如同为 CERT_EXPIRED，区分证书到期与客户端仍选旧证书。它们均有明确不适用范围，仍共享十二种环境模板。

冻结 SHA-256：`75816af340a6b9c6b33cafd28523204c847e713c507b0ffaf72c1df851d4d104`。

独立 LLM 上下文审读了固定随机抽样 60 题及全部 50 道跨段题，去重后为 **99/300 题**。发现并修正五处问题：两处升级证据用“三个时间值/两类位点”代指未标第三段的信息，三处问句缺关键恢复前提。修订均在查看新题分数前完成，初版与审查请求保留。独立代理曾遇用量限制，主代理完成修订和冻结；代理恢复后核对修订，并抽读最终 24/600 篇干扰（十二变体各两篇，覆盖十八个 scenario），未发现应补主 Gold 的文档。这次最终抽查在冻结和开跑后完成，审查者没有查看成绩，也没有改题。

全量机械核查覆盖 300 题、350 条证据和 658 篇输入，实际调用生产 splitter，映射错误、范围冲突、跨集家族重叠均为零。去掉共享范围前缀后，44,850 对问句字符相似度没有达到 0.8 的题对。字符检查不能排除语义近重复；文档近重复则是有意的干扰输入。以上核验仍是 LLM 审查，剩余问题只做了机械检查，**不能称人工专家 Gold**。

## 3. 主结果

Recall@k 是逐题必需 Gold 子段覆盖率的宏平均；双 Gold 命中一段得 0.5。MRR 取前五名中第一个 Gold 的倒数排名，找齐全部证据另外算 AllGold@5。双 Gold 题的 Recall@1 上限为 0.5，因此本测试集整体 Recall@1 理论上限为 0.9167。

每个规模、每个方法有 240 道不同测试题，三个干扰集合共 720 次调用。下表是三组等权平均，不能称 720 道独立新题。

| 文档数 | 方法 | Recall@1 | Recall@3 | Recall@5 | MRR | AllGold@5 |
| ---: | --- | ---: | ---: | ---: | ---: | ---: |
| 64 | 同口径纯向量 | 0.607 | 0.772 | 0.775 | 0.745 | 0.733 |
| 64 | BM25-only | 0.613 | 0.776 | 0.776 | 0.753 | 0.725 |
| 64 | 当前混合 | 0.607 | 0.825 | 0.825 | 0.771 | 0.785 |
| 256 | 同口径纯向量 | 0.569 | 0.690 | 0.738 | 0.697 | 0.696 |
| 256 | BM25-only | 0.613 | 0.776 | 0.778 | 0.753 | 0.726 |
| 256 | 当前混合 | 0.625 | 0.813 | 0.821 | 0.775 | 0.781 |
| 512 | 同口径纯向量 | 0.540 | 0.638 | 0.673 | 0.659 | 0.617 |
| 512 | BM25-only | 0.619 | 0.779 | 0.779 | 0.758 | 0.726 |
| 512 | 当前混合 | 0.631 | 0.789 | 0.799 | 0.767 | 0.758 |

混合相对纯向量的 Recall@5 差值分别为 **+5.00/+8.26/+12.57 个百分点**。512 篇的三组差值为 +12.92/+12.29/+12.50 个百分点；混合自身 Recall@5 范围为 0.792–0.804，纯向量为 0.667–0.677。

先按同题平均种子，再按完整问题家族配对 bootstrap（40 家族、4,000 次、seed 7301），512 篇 Recall@5 差值的描述性 95% 区间为 **+9.51 至 +15.63 个百分点**。这只刻画此合成家族集合的不确定性，不能当真实用户分布的置信保证。

64→512 篇时，纯向量平均 Recall@5 下降 10.21 个百分点，混合下降 2.64 个百分点。逐题成对比较的 720 次同题/种子调用中，混合有 40 次退化、21 次提升、659 次持平；纯向量有 90 次退化、630 次持平。增加文档也会改变 BM25 的词项权重，结果不保证单调变化。

## 4. 哪些问题有效，哪些仍然较差

512 篇下各题型均有 40 道不同测试题、三组运行。数值为 Recall@5，双段一行另列找齐两段的比例。

| 题型 | 纯向量 | BM25-only | 混合 |
| --- | ---: | ---: | ---: |
| 精确术语/错误码 | 0.992 | 0.975 | 1.000 |
| 含版本范围前缀的口语核查 | 0.267 | 0.708 | 0.558 |
| 条件恢复 | 0.950 | 0.950 | 0.967 |
| 验收观察 | 0.492 | 0.533 | 0.658 |
| 安全边界 | 0.725 | 0.850 | 0.850 |
| 跨段证据覆盖 | 0.613 | 0.658 | 0.758 |
| 跨段两段都齐（AllGold@5） | 0.275 | 0.342 | 0.517 |

总体收益主要来自词法路抵抗近邻语义干扰；512 篇的 BM25-only 已达到 0.779，混合只比它高 1.94 个百分点。口语核查子集反而低于 BM25-only 15 个百分点，说明融合排序会损伤部分原本较好的词法排名。它们仍带明确产品/版本/环境前缀，未覆盖真实用户省略条件的口语请求。

跨段题混合 MRR 为 0.931，却只有 0.517 找齐两段；不能用高 MRR 代表完整证据充分。512 篇混合的父文档覆盖为 0.9986，严格子段覆盖只有 0.7986。父块回填通常已提供整篇正文，因此子段缺失也不能直接解释成生成回答缺事实；完整问答正确性需要另一轮生成与事实核验。

## 5. 逐题退化和失败归因

全矩阵为 9 个索引 × 300 题 × 3 方法，共 **8,100 次检索调用，运行异常 0 次**。这不代表全部召回成功：混合的 2,160 次测试调用中，**487 次未找齐 Gold**，逐题结果完整保留。

按记录的候选和固定参数精确重放全部 2,700 条混合结果（含开发集），重放与现场 ID 排名完全一致。对测试集遗漏的 487 个 Gold 子段按实际执行顺序定位：

| 首次丢失位置 | 遗漏 Gold 数 |
| --- | ---: |
| 两路候选都没有 | 5 |
| 原始 RRF Top-10 截断 | 28 |
| RRF 后同来源最多两段的限制 | 449 |
| 最终 Top-5 截断 | 5 |

多数轨迹是同一正确文档的其他段先占满两个位置，答案段随后被来源上限排除。这里是固定流程下的定位，改变上限或顺序的真实效果尚未评估，本轮没有据测试分数试参数。

512 篇相对纯向量的 Recall@5 成对比较为 112 次提升、4 次退化、604 次持平。四次退化涉及两道双段题：`samba_acl-q6` 在三个种子均丢一段，`outlook_profile-q6` 在 seed 20261104 丢一段；这些行的 MRR 可以保持不变，均已保留。

## 6. 鲁棒性、旧题和失败记录

独立探针库以 64 篇主样本加 8 篇生命周期文档开始，共 72 篇，未混入主矩阵的规模或 Recall 分母。先把八篇探针临时设为有效，确认两种方法分别能召回，再恢复冻结的过期/删除元数据。

- 4 个过期和 4 个软删除探针均被两种方法排除，8/8 通过，所有基线均实际暴露。四篇软删除文档再物理删除，子块与父块按 ID 读取均不存在。
- 4 个未覆盖适用范围的无答案探针，两种方法都返回了非空候选。这里只能说明检索不会因范围未覆盖自动变成空结果，没有测试生成层是否澄清或拒答，不能写成拒答通过。
- 探针使用隔离 legacy Chroma，变更后重建 BM25；未测试 Git generation deny、回滚、并发缓存失效或生产删除权限。

旧 16 篇/80 块/60 题在独立索引和真实 Embedding 下单独复测，完全复现原口径：纯向量 Recall@1/3/5=0.600/0.783/0.850、MRR=0.697；混合=0.750/0.883/0.917、MRR=0.819。旧题已用于过去调参，且只保留首 Gold，不能与新题合并成“360 道独立测试”。

运行保留了一次失败准备：`run-01` 在首个 64 篇索引原始向量校验处终止，尚未执行新题检索。评测工具错误地用单位归一化值核对 raw getter，实际存储与 API 原值一致。修正为对比原始输入，以相同冻结输入重跑为 `run-02`，并补非单位向量回归测试；首次 API 事件、日志、失败记录和源码快照均保留。没有丢弃已得出的坏分数，也没有更改业务算法。

## 7. 向量计算、缓存和耗时

向量按清洗文本、模型、维度和 endpoint 组成的键缓存，实际向量文件另存 SHA-256。每批最多 64 条，评测请求超时 30 秒、SDK 重试为零；本轮没有触发 API 失败或重试。主输入池全部子段共 3,948 条，其中 48 条属于独立探针，不代表主索引有 658 篇。内容嵌入 62 批耗时合计 46.97 秒；300 条新题查询嵌入 5 批合计 **3.046 秒**，批次中位 **590.8ms**。这包含供应商与网络时间，不能除以批大小当线上单问延迟，五个批次也不足以给 API p95。

成功的 `run-02` 全部复用 `run-01` 的真实向量，不再调用 API。含预检、旧题、内容、新题和探针，本轮实际记录 **71 次请求、4,385 条输入、供应商计量 437,645 tokens，API 异常 0 次**。这是调用与用量记录，没有核对账单或换算费用。

检索计时不含查询向量计算，包含现有检索、过滤、父块回填。BM25 在测量前显式构建，方法顺序轮换，每档每方法有 720 次测试调用。下表为三组调用池的本机描述性中位数/p95（ms）。

| 文档数 | 纯向量 median / p95 | 混合 median / p95 | BM25-only median / p95 |
| ---: | ---: | ---: | ---: |
| 64 | 10.80 / 21.83 | 12.25 / 24.05 | 1.99 / 2.75 |
| 256 | 16.56 / 27.31 | 23.11 / 34.89 | 6.25 / 8.25 |
| 512 | 26.24 / 37.23 | 39.91 / 53.30 | 13.71 / 17.33 |

三轮中位 Chroma 批量写入为 0.412/2.223/4.829 秒，BM25 首次构建为 0.204/0.854/1.750 秒，均与上表查询时间分开。索引新建后立即测量，应用和 BM25 已暖，操作系统页缓存未清；本机未做 CPU 隔离，独立审查约 1.3 秒机械检查可能与计时重叠。以上不是冷启动端到端耗时或生产 SLO，也不能拿批量建索引时间冒充现有同步生命周期耗时。

> 构建 300 道带段落证据的合成运维检索评测集，按问题家族隔离 60 道开发题与 240 道测试题；基于真实 Embedding-3/Chroma，在 64/256/512 篇同领域干扰语料上进行三组固定种子的配对评测，512 篇测试集混合检索 Recall@5 从纯向量 67.3% 提升至 79.9%（+12.6 个百分点），保留逐题结果、配置哈希和失败归因。

这句话描述既有混合方案的受控比较，本轮没有优化业务检索算法。若简历空间有限，保留“合成”“240 道测试题”“512 篇”“同口径纯向量对照”，不要改成问答准确率、真实用户准确率、生产容量或本轮调优前后提升。

下一步应在开发集研究来源多样性与子段选取的取舍，并分别核验父块上下文下的答案事实；新增缺少范围前缀的真实风格问句、同版本同环境的冲突前提、跨文档证据和专家抽审。冻结测试集不用于反复选参，本轮保留的不足不因有简历数字而视为解决。
