# 可靠性修复与评测记录（2026-11-01）

本轮修复多格式解析、知识同步、证据门禁和单机过载保护。评测覆盖这些变更的确定性行为，并补跑真实检索、真实问答。没有提交、部署或切换在岗知识库。

## 结论与适用范围

修复前已复现的丢内容、解析失败误删、证据否定仍生成等问题已留下回归。当前具备单机有界执行和持久请求去重，但仍未达到生产验收条件。真实问答中 3 道澄清题全部失败，2 道调用故障；不能用单元测试通过率替代这个结论。

当次评测回答模型为 `glm-4.5-air`，Embedding 为 Embedding-3。该评测完成后，用户要求默认模型切换为 `glm-5.3-flash`；本文中的 29 题成绩仍属于旧模型，尚未用新模型重跑。真实评测用 16 篇 Markdown 的独立 80 块索引，没有生产数据库写入、active 切换或外部运维动作。Office、PDF 和视频验证使用程序生成的文件，视觉转译被替代，不代表真实 OCR/ASR 识别质量。

## 改动如何解决问题

| 问题 | 修复与验证 |
|---|---|
| Word 前导正文、无标题表格丢失 | 保留没有标题的正文和表格，按原顺序组装；合成 DOCX 回归 |
| 混合 PDF 漏扫描页 | 逐页判定，文字与需要转译的页面同时入库；文本页带栅格图也进入视觉路径 |
| PPT 图片错配正文页 | 保留空正文页的章节位置，原始页号对应正确章节 |
| 视频只覆盖开头 | 两遍解码后均匀取帧，保留时间戳并覆盖末帧；音轨仍只取配置的前 N 秒 |
| 解析失败被当成删除 | 保留旧台账、旧向量，报告失败；根目录不存在时中止 |
| 嵌入失败先丢旧块 | 先嵌入、写入并验证全部块的 ID、正文和 doc_hash，再清理多余旧块；模拟静默部分写入不能误报成功 |
| 不完整候选可发布 | 持久 build_ready 标记，构建/切换同机互斥；空库和失败库不能切换 |
| 裁判否定或异常仍生成 | judge 必需字段严格校验；只有明确 enough=true、answerable=true 才调用生成；取消高分/BM25 绕过 |
| 重复请求重复运行 | AgentRequest 表保存请求指纹和终态 SSE；同 request_id 同内容重放，不同内容 409，未知终态保守 409 |
| 同会话同时执行 | 非阻塞会话锁，忙时 409；进程退出释放本地文件锁 |
| 突发请求占满资源 | 认证前在途预算 16、执行预算 8；超限 503 + Retry-After；同机 worker 共享锁目录 |
| 认证连接池饥饿 | 身份读取后脱离 ORM Session 并归还认证连接；实际 HTTP 压测发现并复测 |
| SSE 断线丢业务字段或漏锁 | 节点同时携带业务状态快照；结束/传输异常时等当前同步步骤结束后清理；大中文终态使用 MySQL LONGTEXT |

SQL 与 Chroma 没有共同事务。部分 upsert 失败可能留下候选中间态，发布门禁阻止其上线；直接对在岗库调用增量引擎仍没有完整版本隔离。候选发布保留全量重建，未把现有增量收益冒充本轮新增优化。

## 真实问答：29 题全部完成

真实运行检索、证据裁判和生成。单次模型超时 10 秒，SDK 不重试，问答主链单题预算 20 秒。复用最初已完成的 6 题与向量库，前后两阶段真实问答累计约 385 秒。辅助质量指标出现超时后，剩余题显式跳过它们，报告保留缺失值。

| 预期行为 | 总数 | 行为达标 | 行为不达标 | 调用故障 |
|---|---:|---:|---:|---:|
| 回答 | 23 | 22 | 0 | 1 |
| 拒答 | 3 | 2 | 0 | 1 |
| 澄清 | 3 | 0 | 3 | 0 |
| 合计 | 29 | 24 | 3 | 2 |

故障分别为 e02 裁判格式不合格、e08 裁判超时。两者安全拒答，但不计作质量成功。报告中的 answer_behavior_accuracy=1.0 分母是 22 道有判分回答题，refusal_accuracy=1.0 分母是 2 道有判分拒答题；不能写成 23/23 或 3/3。

Gold Answer 关键词平均覆盖 0.874，Gold Chunk 平均覆盖 0.543；关键词分数不等于语义正确率。faithfulness 没有有效结果，切题度 0.831 仅为最初 6 题抽样。两个预期多跳样本本次均未实际完成多跳，不应再以“有多跳循环”证明多跳问答有效。

3 道澄清失败来自返回泛化指南，没有明确收集错误码、设备、客户端等必要信息。当前门禁能挡住程序在裁判否定时放行，但合法裁判仍可能批准不适合直接回答的问题，生成也可能添加证据外内容。这些问题需要下一轮单独设计澄清策略和事实核验。

## 本地 HTTP/SSE 过载实验

硬件：macOS 15.6.1 arm64，8 逻辑 CPU，Python 3.12.13；一个 Uvicorn worker；临时 SQLite WAL，连接池 16。真实走 HTTP、认证、路由、持久化及 SSE，替身 Agent 延迟 150ms，模拟上游并发预算 8。它不代表真实 LLM 响应时间、供应商配额、MySQL 或多机容量。

| 条件 | 完成 | Agent 错误 | HTTP 500 | 明确 503 | 请求超时 |
|---|---:|---:|---:|---:|---:|
| 100 并发，关闭准入对照 | 17 | 43 | 40 | 0 | 0 |
| 100 并发，开启准入 | 8 | 0 | 0 | 92 | 0 |
| 1000 请求，客户端并发 200，开启准入 | 334 | 0 | 0 | 666 | 0 |

关闭准入的对照使用本轮代码，只关闭入口预算和执行锁；它不是完整旧代码基准。两轮保护实验的执行峰值均为 8、模拟上游超载为 0，所有接纳请求最终完成。503 是未接纳，不是用户获得答案。1000 次请求也不等于 1000 个同时执行。

100 并发保护组：成功请求 p95=356.64ms，503 p95=249.68ms。1000 请求组：成功 p95=6728.21ms，503 p95=6777.40ms，突发负载下仍有明显长尾，不能宣传为全部快速响应。耗时包含本机 HTTP 客户端、服务端和数据库竞争。

首次实验还复现认证连接池饥饿：100 请求均超时。该失败记录保留在 http_initial_auth_starvation_100.json。修复认证连接释放并增加认证前入口预算后，产生上述结果，未隐藏初次失败。

## 上线与学习说明

`init_db()` 会创建新增的 agent_requests 表，本轮没有在真实数据库执行迁移。需重启应用、在测试环境验证建表与权限后再部署；老候选没有 build_ready 标记，需要重新同步才能发布。Docker 的锁目录与索引共用持久卷；同机多 worker 的预算、锁目录必须一致。

新增 request_id 是一次逻辑请求的身份证：同一轮网络重试复用它，而用户主动提出新请求应生成新键。数据库记住终态后，重试直接读取结果。请求已执行但进程在结果落库前崩溃时，系统不确定外部副作用是否成功，因此返回 409，保留人工核验需求；不能仅靠超时就再次执行。

入口预算保护数据库和线程资源，执行预算保护 Agent，下游可能被每轮多个并行模型调用进一步放大。当前没有供应商账号级配额调度、分布式锁、多主机容量证据、自动 pending 恢复或整轮可取消硬截止时间。长会话、PDF大页数、长视频解码与跨进程 BM25 缓存一致性仍需专项治理。
