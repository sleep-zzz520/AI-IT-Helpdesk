# Git 增量同步旧新版本对照结果（2026-11-02）

本轮没有证明同步整体显著提速。较明确的新增收益是减少源文档解析与切分，以及解析实现指纹变化时不再连带失效全部向量；整代逐文档写入仍是本地实验的主要耗时。新增故障用例还暴露了候选向量内容完整性边界。

主对照为完整 Git 初版 `576d093` 与当前业务代码 `8b0dd00`。两者都已有增量、向量复用与版本发布，没有使用全量重建作主基线。没有修改业务同步代码、提交或部署。

## 数据、环境与分母

- 从本地 10,000 篇 CRUD-RAG 衍生文本池按长度分层并补充长尾抽样，加上 16 篇项目知识文档；累计涉及 3,130 个不同源文件，原始文件 SHA-256 全部复核一致。不是一万篇同时入库，也不是实际企业用户数据。
- 64 / 256 / 512 篇三档，每档五个固定种子的独立配对轮次；冷构建加七类变更，共 240 个版本/场景试验，即 120 对。所有正常路径通过独立正文、元数据、有序子块和向量 oracle。
- Apple M1、16 GiB、macOS 15.6.1，Python 3.12.13、Chroma 1.5.9、SQLAlchemy 2.0.51、OpenAI SDK 2.52.0；真实临时 SQLite/Chroma，确定性 SHAKE256 1024 维向量，无真实模型请求。
- 原生指纹校准另有 64 篇三轮的 18 个试验，以及 512 篇一轮的 4 个试验，全部通过；不与主矩阵混合统计。

## 计量口径修正

主矩阵 v1 预计算并冻结了处理版本指纹，省掉了生产中的重复指纹计算；这项适配并非计数所必需。以下 v1 时间是适配生命周期时间，不能称为原生端到端。计算量、真实 upsert 包含时间和输出正确性仍按该口径保留。原计量脚本和 SHA-256 已归档。

v2 默认保留原生指纹计算，安装计数前后断言指纹一致。身份断言在计时外，并清空其统计；指纹时间包含嵌套调用，不能跨函数直接相加。512 篇仅一对校准，不计算 bootstrap 区间，也不据此宣称微小速度差异。

## 相同输入下的计算量

以下为五轮中位数，解析与切分统计函数执行次数，包含同篇文档在多个阶段的重复调用。

| 规模 | 场景 | 旧版解析/切分/嵌入 | 新版解析/切分/嵌入 |
| ---: | --- | ---: | ---: |
| 64 | 解析源码指纹变、输出不变 | 256/128/119 | 64/0/0 |
| 64 | 字节不变的新提交 | 256/128/0 | 0/0/0 |
| 256 | 解析源码指纹变、输出不变 | 1024/512/416 | 256/0/0 |
| 256 | 字节不变的新提交 | 1024/512/0 | 0/0/0 |
| 512 | 解析源码指纹变、输出不变 | 2048/1024/687 | 512/0/0 |
| 512 | 字节不变的新提交 | 2048/1024/0 | 0/0/0 |

普通正文、元数据和改名场景中，两版的嵌入输入量相同。不能将旧版已有的向量复用算作最新优化；元数据更新零嵌入也不是新版独有收益。

## 总耗时和真实写入成本

主矩阵无变化新提交的五轮中位数如下。v1 适配时间不代表原生部署延迟；不同轮次的语料长度也不同。

| 规模 | 旧版 v1 秒 | 新版 v1 秒 | 新版 upsert 包含时间 / 总时间的逐轮比值中位数 |
| ---: | ---: | ---: | ---: |
| 64 | 3.658 | 3.564 | 73.0% |
| 256 | 67.262 | 67.148 | 92.6% |
| 512 | 152.125 | 151.724 | 95.3% |

512 篇 r0 新版仍执行 512 次 upsert、写入 1,222 块；约 150 秒在原始 Chroma upsert 调用内部。尚未区分 HNSW、事务、日志、落盘或其他内部工作，不能断言某一种算法复杂度。确定性替身向量也未校准真实语义向量分布。

原生指纹校准的无变化场景：

| 规模 / 配对轮次 | 旧版原生秒 | 新版原生秒 |
| --- | ---: | ---: |
| 64 / 3 | 3.432 | 3.378 |
| 512 / 1 | 157.901 | 158.405 |

这些数据支持“缓存减少重算”，不支持“同步整体大幅提速”。当前每代完整索引写入仍是主要成本；批量写入等方案需要另做实验，尚未实施。

## 64 篇故障验证

| 场景 | 结果 |
| --- | --- |
| 解析/切块缓存损坏 | 符合保护预期 |
| 向量缓存损坏并触发重算 | 符合保护预期 |
| 503 分类持久退避 | 符合保护预期 |
| 401 不自动重试 | 符合保护预期 |
| 实际部分写入后失败 | 符合保护预期 |
| prepared 后缺块拒绝发布 | 符合保护预期 |
| prepared 后合法维度错误向量 | 未阻止发布，独立向量 oracle 发现不匹配 |
| 旧 prepared 被新意图取代 | 符合保护预期 |
| 删除、构建失败和实际回滚 | 符合保护预期 |

不能把九种故障类型换算为线上失败概率。未通过项限定于 prepared 后底层候选被直接修改；不证明正常同步会自行产生错误向量。503 场景推进测试时钟，只证明持久字段和等待门禁，不证明实际恢复时延。

源验证另测四个边界：513 篇拒绝、单篇超过 2 MiB 拒绝、原文合计正好 16 MiB 接受、超过 16 MiB 拒绝。16 MiB 只是源输入校验，不包含该边界下的索引构建或容量验收。
