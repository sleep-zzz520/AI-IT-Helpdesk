# Git 增量同步：阶段缓存、有限重试与恢复验证

本轮补齐三项能力：解析和切分阶段缓存、持久化的分类重试、进程崩溃及备份恢复验证。适用范围仍是单机、共享知识源、Git Markdown；不能据此声称整个知识平台已达到企业级。

## 1. 不变文档跳过哪些工作

缓存分为三层。解析结果按原始字节摘要与解析器版本保存；切分结果按解析输出、切分规则和文档身份保存；向量按实际发送给供应商的文本与嵌入配置保存。解析器升级但输出不变时，重新解析，继续复用切分和向量。仅修改元数据时重建对应块的元数据，复用正文向量。

命中缓存仍检查输入路径、文件大小、字节摘要、文档 ID 和产物结构。每次发布仍核验完整索引，并写入一代独立的完整 Chroma collection；本轮减少的是解析、切分和嵌入工作，没有消除整代索引复制。

以固定 Git 提交 `1ac31e7` 的 16 篇文档为基础，在隔离 MySQL 8.0.43 来源和临时 Chroma 中执行真实 Embedding-3 调用。修改提交为合成场景。计数器包在真实函数入口，覆盖入队、处理、发布全过程，避免只看 worker 报表而漏掉导出阶段的重复解析。

## 2. 失败后如何处理

同步任务把失败分类、尝试次数和下次执行时间写入 SQL。临时连接故障、超时、部分数据库错误、HTTP 408/409/429/5xx 可以重试；鉴权、输入错误、存储空间不足和完整性错误直接失败。最多执行三次，包含首次执行；采用带随机扰动的指数退避，遵守供应商 Retry-After，自动等待上限为 300 秒。任务等待期间释放数据库事务和 worker 执行权。

HTTP 429 不能一概视为短时限流。智谱的欠费、套餐过期、长周期额度等业务码需要人工处理；分类依据为[智谱官方错误码说明](https://docs.bigmodel.cn/cn/api/api-code)。每次任务尝试中的嵌入请求只执行一次，避免任务重试与 SDK 重试相乘。已经成功的批次立即保存向量缓存，后续失败不要求重算成功批次。

针对真实 SDK 请求边界注入 HTTP 503，在单批次持续失败场景验证三次任务尝试合计只发出三次请求，而非九次。其他测试覆盖延迟领取、429 业务码、Retry-After、永久错误、部分批次成功、更新任务取代旧任务，以及失败记录本身遇到数据库故障后的租约回收。管理页显示等待重试、下次执行时间和已记录的处理数量；返回安全摘要，避免把供应商原始错误正文暴露给用户。

## 3. 恢复能力验证到了哪里

本地脚本启动独立 worker 子进程并真实发送四次 SIGKILL，分别发生在任务入队后、实际写入一个块后、恢复至待发布后、发布完成后。进程重新启动后检查任务状态、完整块清单、父块正文、已发布指针，以及删除文档不会被回滚恢复。

本次四个故障点通过，恢复等待观测为 2212.48 ms。演练把租约从生产的 120 秒缩短为 2 秒，这个耗时不能作为生产恢复 SLO。停写后使用 SQLite backup API 和目录复制，再恢复到另一目录：33 个文件、453467 字节，文件摘要、generation、文档和父块一致，SQLite integrity_check 为 ok。原始记录：[进程恢复 JSON](../backend/tests/quality_reports/sync_recovery_process.json)。此脚本使用确定性八维向量，不验证供应商质量；SIGKILL 不等于机器掉电，未证明磁盘断电后的持久性。

生产发布流程另做两项检查：

1. 重建服务后、发布新知识前，确认上一代指针及正文/元数据摘要与停写备份相同。
2. 将停写备份的两张知识表导入随机隔离 MySQL schema，在临时目录解压 Chroma 和同步快照，校验清单、向量、正文、删除限制与真实双路检索、父块回填。使用已存储向量，不新增 Embedding 或 LLM 调用。完成后删除临时目录、数据库和授权。

每次发布的实际结果保存在 Actions 的 `knowledge-restore-evidence` artifact。恢复检查操作知识子系统备份，不覆盖生产库，也不代表完整系统灾难恢复、跨机器容灾或备份保留策略已经完成。归档路径、符号链接、大小和目标数据库均有前置校验；SQL 预检只适用于工作流自身生成的受控 mysqldump，不是任意 SQL 的安全沙箱。

## 4. 回归与检索结果

本轮本地后端 415 项测试通过，前端 16 项通过，后端 Ruff、前端 lint/build 通过。前端保留两条已有 Hook 依赖警告；后端依赖存在弃用警告。

真实 Embedding-3 的 60 题检索对照中，全量参考与新版 Recall@5 均为 0.917，Recall@3 均为 0.883；Recall@1 分别为 0.733 / 0.750，MRR 为 0.811 / 0.819。本轮没有为这点差异设计多轮统计对照，不把它归因于缓存优化。原有未召回问题仍存在；这些是检索指标，不是回答准确率，也不是 GLM-5.3-Flash 的端到端问答测评。原始记录：[真实检索与增量对照 JSON](../backend/tests/quality_reports/git_generations_hardened_real.json)。
